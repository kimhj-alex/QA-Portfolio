About the App

Shoebox Planner is a drag-and-drop 2D room planning tool built from scratch as a PWA — designed for desktop and tablet use. Users can create rooms, place and customize furniture items, adjust sizes and colors, manage layers, and save or export their layouts. This audit was conducted by the developer as an objective self-assessment of the current beta release across desktop and iPad environments.

Testing Approach

Testing followed a structured checklist covering all core features, executed first on desktop then repeated on iPad to identify platform-specific regressions. Features that passed on both platforms were marked complete. Bugs were documented where behavior deviated from expected. Where a desktop bug could not be reproduced on iPad due to other blocking bugs, it was noted as untestable rather than passed.

This app is also the subject of a Gen AI case study — a look at an AI coding assistant's reasoning failures while building its ellipse-collision math, found through testing rather than code review.

Individual Findings

Severity: Medium Found Apr 2026 Desktop · iPad

The undo function behaves inconsistently depending on whether the user is working with a new room or a saved room. In a new room, undoing after adding placeholder furniture correctly removes the item. In a saved room, the same undo action does not remove placeholder furniture — the item remains even after multiple undo presses. This inconsistency means undo is unreliable as a correction tool in saved rooms, which is where users are most likely to be making deliberate edits.

Steps to Reproduce

  1. 1.Create a new room and add placeholder furniture — press Undo — observe furniture is removed correctly
  2. 2.Save the room and reopen it from the Saved Rooms list
  3. 3.Add placeholder furniture to the saved room
  4. 4.Press Undo
  5. 5.Observe: placeholder furniture is not removed — undo has no effect on newly added items in a saved room

Expected Result

Undo removes the most recently added furniture item consistently, regardless of whether the room is new or loaded from a saved state.

Actual Result

Undo works correctly in new rooms but has no effect on placeholder furniture added to saved rooms. The undo history appears to reset or not initialize correctly when a saved room is loaded.

Severity: Low Found Apr 2026 Desktop only

On desktop, clicking a furniture item in the room correctly highlights the corresponding layer in the left panel. The reverse is not true — clicking a layer in the panel does not highlight or select the corresponding furniture item in the room canvas. This breaks the expected bidirectional relationship between the layer list and the canvas, making it harder to identify which furniture item corresponds to a given layer when the room is complex. Note: this works correctly on iPad, making it a desktop-specific regression.

Steps to Reproduce

  1. 1.Open the app on desktop and create a room with multiple furniture items
  2. 2.Click a furniture item in the room canvas — observe its layer highlights in the left panel
  3. 3.Click a different layer in the left panel
  4. 4.Observe: the corresponding furniture item in the room canvas does not highlight or become selected

Expected Result

Clicking a layer in the panel highlights and selects the corresponding furniture item in the room canvas — mirroring the behavior that already works in the opposite direction.

Actual Result

Clicking a layer in the panel has no effect on the canvas selection. The interaction is one-directional only on desktop. Works correctly on iPad.

Severity: High Found Apr 2026 Desktop only Not testable on iPad — color controls blocked by RP-007

When a user moves one furniture item and then changes the color of a different furniture item, pressing undo multiple times causes incorrect behavior — the undo stack applies changes to the wrong furniture item. On the second undo press, either the first item moves unexpectedly or the second item's color changes instead of reverting the intended action. The undo history appears to mix state between different furniture items rather than tracking each item's history independently.

Steps to Reproduce

  1. 1.Create a room with at least two furniture items
  2. 2.Move Item A to a new position
  3. 3.Change the color of Item B
  4. 4.Press Undo once — observe Item B's color reverts (correct)
  5. 5.Press Undo again
  6. 6.Observe: Item A moves unexpectedly, or Item B's color changes again instead of Item A reverting to its original position

Expected Result

Each undo press reverts the most recent action in the correct sequence — second undo moves Item A back to its original position, regardless of which item was acted on most recently.

Actual Result

The undo stack does not correctly isolate actions by item — multi-step undo bleeds between furniture items, applying position or color changes to the wrong item. Not testable on iPad as color controls are non-functional (see RP-007).

Severity: Medium Found Apr 2026 Desktop only Not testable on iPad — layer reorder blocked by RP-005

When a room is saved and reopened, the layer order of furniture items is not preserved. Items appear in a default order rather than the custom order the user had arranged. Hidden layer state is saved and restored correctly — only the order is lost. This means any deliberate layering decisions made by the user are discarded on save, requiring them to manually re-arrange layers every time a saved room is opened. Not testable on iPad as layer reordering itself is broken on touch (see RP-005).

Steps to Reproduce

  1. 1.Create a room with multiple furniture items and arrange layers in a custom order
  2. 2.Save the room
  3. 3.Return to the home screen and reopen the saved room
  4. 4.Observe: furniture items are present but layer order has reverted to default
  5. 5.Note: any hidden layers are correctly restored as hidden

Expected Result

Reopening a saved room restores all furniture items in the exact layer order they were in when saved.

Actual Result

Layer order is not saved. Furniture items reappear in default order. Hidden layer state is preserved correctly, confirming the save mechanism is partially working but not capturing layer position data.

Severity: High Found Apr 2026 iPad only

On iPad, the layer panel on the left side of the screen does not scroll reliably. Attempting to scroll the panel by dragging anywhere except the very edge of the panel instead triggers the drag-to-reorder behavior, moving the furniture layer rather than scrolling the list. This makes the layer panel effectively unusable for scrolling on touch when a room has more layers than fit on screen — users cannot navigate the full layer list without accidentally reordering items.

Steps to Reproduce

  1. 1.Open the app on iPad and create a room with enough furniture items to require layer panel scrolling
  2. 2.Attempt to scroll the layer panel by dragging in the center of the panel
  3. 3.Observe: the drag gesture reorders the furniture layer instead of scrolling the list
  4. 4.Attempt to scroll by dragging on the very edge of the panel
  5. 5.Observe: scrolling works only from the edge

Expected Result

The layer panel scrolls reliably when dragged anywhere within it. Drag-to-reorder is triggered only by a clearly distinct gesture (e.g. long press and drag on the drag handle).

Actual Result

Scroll and reorder gestures conflict — dragging anywhere except the edge triggers reorder. The layer panel is not reliably navigable on touch.

Severity: High Found Apr 2026 iPad only

On iPad, the context menu for furniture items (containing Hide, Delete, and Unhide options) opens correctly with a two-finger tap or long press, but the menu options cannot be selected with touch. Tapping any option in the menu does not trigger the action. This makes it impossible to hide, delete, or unhide furniture items using touch on iPad, blocking three core furniture management functions entirely on the touch interface.

Steps to Reproduce

  1. 1.Open the app on iPad and create a room with furniture items
  2. 2.Attempt to open the context menu on a furniture item using two touches or a long press
  3. 3.Observe: the context menu opens showing Hide, Delete, and Unhide options
  4. 4.Tap any option in the context menu
  5. 5.Observe: no action is triggered — the option appears tappable but does not respond

Expected Result

Tapping any option in the context menu triggers the corresponding action — hide removes the item from view, delete removes it from the room, unhide restores a hidden item.

Actual Result

The context menu opens but its options are non-interactive on touch. Hide, delete, and unhide are completely inaccessible on iPad.

Severity: High Found Apr 2026 iPad only

On iPad, tapping a color swatch in the furniture layer panel does not change the furniture item's color. The color controls are visible and appear interactive, but tapping any swatch produces no color change on the canvas. Color customization is a core feature of the app — its complete non-functionality on iPad significantly limits the usefulness of the touch interface and blocks related testing (such as verifying undo behavior for color changes on iPad).

Steps to Reproduce

  1. 1.Open the app on iPad and create a room with at least one furniture item
  2. 2.Select a furniture item — observe its layer panel with color swatches is visible
  3. 3.Tap any color swatch in the panel
  4. 4.Observe: the furniture item's color does not change
  5. 5.Repeat with multiple swatches and multiple furniture items — observe color change never triggers on touch

Expected Result

Tapping a color swatch changes the selected furniture item's color to the tapped color, matching the behavior on desktop.

Actual Result

Color swatches do not respond to touch. No color change occurs on iPad regardless of which swatch is tapped or which furniture item is selected.

Improvement Note

The following is a known design limitation identified during testing — not a bug, but a candidate for a future improvement.

Unit Toggle — Label Only, No Value Conversion

The unit toggle switches between cm and px labels but does not convert existing dimension values when toggled. A room set to 600 cm displays as 600 px after toggling — the number stays the same, only the label changes. This was an intentional design decision for simplicity, but user feedback suggests the lack of conversion is confusing. A future improvement could automatically convert values when the unit is toggled, so 600 cm becomes the equivalent pixel value and vice versa.
