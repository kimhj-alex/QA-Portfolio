Severity: Medium Priority: Medium Open macOS · Brave · github.com

Users cannot create folders through any visible UI control. The only method requires typing a slash character inside a filename field — a convention with no tooltip, label, or hint anywhere in the interface. Discovered only after consulting an external tool (ChatGPT). New or non-technical users have no way to discover this without leaving the platform entirely.

Steps to Reproduce

  1. 1.Navigate to any repository on github.com
  2. 2.Click Add file → Create new file
  3. 3.Attempt to create a folder to organize repository files
  4. 4.Search the interface for a folder creation button, menu option, or any visible UI control
  5. 5.No control exists — method only discovered via external search (ChatGPT)

Expected Result

A visible affordance (button, tooltip, or placeholder text) indicates how to create folders within a repository.

Actual Result

No folder creation UI exists. The only method — typing a slash in the filename field — is entirely undisclosed in the interface. Users who don't already know this cannot proceed without external help.

Severity: High Priority: High Open macOS · Safari · github.com

GitHub Pages provides no real-time deployment status updates, no propagation delay warnings, and no indication that rapid consecutive commits will cancel in-progress deployments. When a user uploads a replacement file and the live site does not update immediately, there is no guidance on whether to wait, refresh, or take action. This causes users to troubleshoot a problem that doesn't exist — triggering more commits that cancel previous deployments and extend the delay further. Even after all checks pass, propagation to the live site is inconsistent across devices and can take 6+ minutes on mobile with no user-facing explanation.

Steps to Reproduce

  1. 1.Navigate to a GitHub Pages repository and open a file in an images folder
  2. 2.Delete existing file and commit
  3. 3.Without waiting for deployment to complete, upload a replacement file with the same name and commit
  4. 4.Observe: deployment checks are cancelled (✗ 0/3) with no warning that the previous deployment was interrupted
  5. 5.Attempt to monitor deployment progress — page does not update in real time, requires manual refresh
  6. 6.Wait for all checks to pass (✓ 3/3) — confirm on desktop browser that site has updated
  7. 7.Check same page on mobile — observe site has not updated despite successful deployment

Expected Result

GitHub provides real-time deployment status updates, warns users before a new commit cancels an in-progress deployment, and communicates that propagation may take additional time after checks pass — especially across different devices and networks.

Actual Result

Deployment status is static until manually refreshed. No warning is shown when a new commit cancels a previous deployment. After all checks pass, the live site updated on desktop but had not updated on mobile after 6+ minutes. No estimated propagation time or device-specific guidance is provided anywhere in the interface.

Notes

Reliable workaround — delete old file, wait for full deployment, then upload replacement — is not documented or suggested by GitHub anywhere. Discovered through extended trial and error. Commit history shows the troubleshooting loop this causes in practice.
Severity: High Priority: High Open macOS · Brave · github.com

The delete button for repository files is not accessible when using the Brave browser. The button either does not appear or cannot be interacted with. GitHub provides no disclosure of browser compatibility limitations, no workaround instructions, and no fallback. Users on Brave cannot delete files through the standard UI. Safari renders the button correctly, suggesting the issue is specific to Brave's script-blocking or rendering behavior rather than a macOS-level problem.

Steps to Reproduce

  1. 1.Open github.com in Brave browser on macOS
  2. 2.Navigate to a repository and open any file
  3. 3.Attempt to locate and interact with the delete (trash) icon
  4. 4.Observe: button is missing or non-functional
  5. 5.Repeat in Safari — button functions normally

Expected Result

Delete functionality works consistently across all major browsers, or GitHub discloses known browser limitations and provides a workaround.

Actual Result

Delete button is inaccessible on Brave. No browser compatibility notice or workaround is provided anywhere in the interface or documentation.

Severity: Medium Priority: Medium Open macOS · Brave · github.com · Pages settings

The custom domain setup flow for GitHub Pages provides DNS configuration instructions that assume significant prior technical knowledge. While GitHub offers both setup and troubleshooting documentation covering record types, IP addresses, and common errors, neither the in-product flow nor the supporting documentation mentions TTL (Time to Live) — a required field during DNS configuration at most providers. The field presents numeric options such as 600 and 3600 with no explanation of what TTL controls, how it affects domain propagation, or which value is appropriate for a standard GitHub Pages setup. Non-technical users must seek external resources to complete this specific step independently.

Steps to Reproduce

  1. 1.Navigate to a GitHub Pages repository → Settings → Pages
  2. 2.Enter a custom domain and follow the DNS configuration prompts
  3. 3.Navigate to your DNS provider to create the required DNS records
  4. 4.Locate the TTL field in the DNS record creation form
  5. 5.Observe that no explanation of TTL, its function, or a recommended value is provided in the GitHub setup flow or linked documentation
  6. 6.Attempt to complete setup without any prior DNS knowledge

Expected Result

GitHub's setup documentation or in-product guidance explains the TTL field, its effect on domain propagation, and provides a recommended value for a standard GitHub Pages configuration.

Actual Result

TTL is not mentioned anywhere in GitHub's custom domain setup flow or supporting documentation. Users encountering the field must determine an appropriate value through external research.
