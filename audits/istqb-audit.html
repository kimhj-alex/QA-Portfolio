Severity: High Priority: High Found Apr 2026 macOS · Safari · istqb.org

The exam provider search filter on the ISTQB website produces inconsistent results depending on language selection, causing valid accredited providers to be excluded entirely. When searching with Country: Republic of Korea, Language: English, and Exam Type: CTFL, the Korea Software Testing Qualifications Board (KSTQB) does not appear in results despite being an accredited provider that offers CTFL. KSTQB only appears when the Exam Type filter is left blank, or when Language is changed to Korean. The filter is actively excluding a valid provider rather than narrowing results correctly, which is a logic error rather than a display issue. Users searching in English for a CTFL provider in Korea receive no results and have no indication that a valid provider exists.

Steps to Reproduce

  1. 1.Navigate to istqb.org → Training & Exams → Find an Exam Provider
  2. 2.Set Country to Republic of Korea, Language to English, Exam Type to CTFL
  3. 3.Click Search
  4. 4.Observe: KSTQB does not appear in results
  5. 5.Remove the Exam Type filter and click Search again
  6. 6.Observe: KSTQB now appears in results
  7. 7.Re-add Exam Type CTFL, change Language to Korean, click Search
  8. 8.Observe: KSTQB now appears in results with CTFL listed under exam info

Expected Result

The search filter returns all accredited providers that match the selected criteria. KSTQB appears in results when filtering by Republic of Korea, English, and CTFL, as it is an accredited provider offering that certification.

Actual Result

KSTQB is completely absent from results when Language is set to English and Exam Type is set to CTFL. The provider only appears when Exam Type is left blank or Language is changed to Korean. No message indicates that results may be incomplete or that a provider exists outside the current filter combination.

Severity: Medium Priority: Medium Found Apr 2026 macOS · Safari · glossary.istqb.org

The ISTQB Glossary page (glossary.istqb.org) offers language selection including English, Spanish, and Korean, but translation is incomplete in two significant ways. First, the Graphs → Mind Maps of FL v4.0 Keywords section remains entirely in English regardless of language selection — the graph renders but all labels and content are untranslated. Second, the number of glossary entries varies significantly across languages: English returns 651 results, Spanish returns 578, and Korean returns 499. A glossary should contain the same terms regardless of display language — the discrepancy suggests that a substantial number of entries have no translation and are silently excluded from results rather than displayed in English as a fallback. Users studying for ISTQB certification in Spanish or Korean are working from an incomplete reference without any indication that entries are missing.

Steps to Reproduce

  1. 1.Navigate to glossary.istqb.org
  2. 2.Set language to English — note total result count (651)
  3. 3.Navigate to Graphs → Mind Maps of FL v4.0 Keywords — note content is fully in English
  4. 4.Change language to Spanish — note total result count (578)
  5. 5.Navigate to Graphs → Mind Maps of FL v4.0 Keywords — observe content remains entirely in English
  6. 6.Change language to Korean — note total result count (499)
  7. 7.Navigate to Graphs → Mind Maps of FL v4.0 Keywords — observe content remains entirely in English

Expected Result

All glossary entries are available across all supported languages. Graphs and visual content are translated or localized when a non-English language is selected. If a translation is unavailable, the entry is displayed in English as a fallback rather than excluded from results entirely.

Actual Result

Spanish returns 73 fewer entries than English and Korean returns 152 fewer entries than English, with no indication that results are incomplete. The Mind Maps graph remains fully in English in both Spanish and Korean with no fallback notice or translation.

Severity: Medium Priority: Medium Found Apr 2026 macOS · Brave · glossary.istqb.org/en_US/quiz

When navigating to the Quiz page on the ISTQB Glossary site, the main content area is entirely empty on load and provides no guidance on how to proceed. The only prompt is light placeholder text reading "Select Syllabus" inside the top bar — the same element that functions as a search field on the Search page. This repurposed element gives no visual indication that its function has changed, and no instructional text explains that selecting a syllabus from it will load quiz content below. Once a syllabus is selected from the top bar, a specific quiz must then be selected from a dropdown, after which the quiz renders in the main grey content area. The interaction path is non-obvious and the page reads as blank and broken on first impression.

Steps to Reproduce

  1. 1.Navigate to glossary.istqb.org
  2. 2.Note the top bar functions as a search field with a magnifying glass icon and "Search..." placeholder text
  3. 3.Click Quiz in the top navigation
  4. 4.Observe: the main content area is entirely empty except for the heading "Keywords Quiz" and the text "Select Syllabus"
  5. 5.Observe: the top bar has changed from a search field to a dropdown labeled "Select Syllabus" with no explanation or instructional text
  6. 6.Click the top dropdown and select a syllabus
  7. 7.Observe: a quiz dropdown appears — select a quiz
  8. 8.Observe: quiz content now renders in the main grey content area

Expected Result

The Quiz page provides clear instructional guidance on how to begin. If the top bar changes function between pages, the change is visually distinct and explained. The content area does not appear blank and broken on load.

Actual Result

The main content area is empty on load with no instructional text. The top bar silently changes function from search field to syllabus selector with no visual distinction or explanation. The interaction path is non-obvious and the page reads as broken until the user discovers the repurposed top bar independently.

Severity: Medium Priority: Medium Found Apr 2026 macOS · Brave · glossary.istqb.org

The ISTQB Glossary offers a downloadable PDF version of search results — a well-formatted document with a title page — but the only access point is a small red printer icon positioned next to the result count in the top right of the content area. The icon has no label, no tooltip, and no descriptive text. The only visual feedback on hover is a color change to burgundy. No download prompt, link, or mention of a PDF appears anywhere else on the page. Other ISTQB certification pages provide downloadable resources in a dedicated, clearly labeled resources section — the glossary does not follow this pattern. Users looking for a printable or downloadable version of the glossary have no obvious path to find it and are likely to miss it entirely.

Steps to Reproduce

  1. 1.Navigate to glossary.istqb.org
  2. 2.Perform any search to return results
  3. 3.Scan the page for a download, export, or print option
  4. 4.Observe: no labeled download or PDF option is visible
  5. 5.Locate the small red printer icon next to the result count in the top right of the content area
  6. 6.Hover over the icon — observe it changes color to burgundy with no tooltip or label
  7. 7.Click the icon — observe a new tab opens and a save dialog appears prompting download of a file named "search result [date]"
  8. 8.Open the downloaded file — observe it is a well-formatted PDF with a title page

Expected Result

The PDF download option is clearly labeled and discoverable — either as a dedicated button, a link in a resources section consistent with other ISTQB pages, or at minimum a tooltip on the icon describing its function.

Actual Result

The only access point for the PDF download is a small unlabeled printer icon with no tooltip. A color change on hover is the sole feedback. The download filename gives no indication it is a full glossary PDF. Users with no prior knowledge of the icon's function are likely to overlook it entirely.

Severity: High Priority: High Found Apr 2026 macOS · Brave · istqb.org

The ISTQB website includes a third-party accessibility widget (Ally by Elementor) accessible via a small blue button in the bottom left corner of the page. The widget button renders only in Brave browser and is entirely absent in Safari, Chrome, and Firefox — meaning the majority of users have no access to any accessibility options regardless of how they navigate. The widget itself is comprehensive — offering text and visual adjustments, orientation options, and personalizations based on user needs. However, the button that opens it has no aria-label, no tooltip, and no descriptive text of any kind. The only visual affordance is a slight size increase on hover. Critically, the button is not reachable via keyboard navigation — tabbing through the page skips it entirely. Users who rely on keyboard navigation or assistive technology cannot access the widget at all. An accessibility tool that is itself inaccessible to the users who need it most is a fundamental contradiction.

Steps to Reproduce

  1. 1.Navigate to istqb.org
  2. 2.Attempt to locate the accessibility widget button by scanning the page — observe it is a small blue button with a white gingerbread-style person icon in the bottom left corner
  3. 3.Hover over the button — observe it grows slightly larger with no tooltip or label appearing
  4. 4.Repeat in Safari, Chrome, and Firefox — observe the accessibility button does not appear at all in any of these browsers.
  5. 5.Attempt to navigate to the button using the keyboard Tab key
  6. 6.Observe: keyboard focus skips the button entirely — it is unreachable without a mouse
  7. 7.Click the button with a mouse — observe a full accessibility options panel opens with text, visual, and orientation settings

Expected Result

The accessibility widget button includes a descriptive aria-label (e.g. "Open accessibility options"), is reachable via keyboard navigation, and displays a tooltip on hover describing its function. The button meets basic accessibility standards independently of the widget it opens.

Actual Result

The button has no aria-label, no tooltip, and no descriptive text. It cannot be reached via keyboard navigation. Users relying on assistive technology or keyboard-only navigation have no way to discover or access the accessibility widget. The button does not render at all in Safari, Chrome, or Firefox — users on these browsers have no access to the accessibility widget.
